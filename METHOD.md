# Method

Copied from the working rubric in `harness/RUBRIC.md` and expanded with what was actually run.

## Claim

Quality of one generation per task, thinking on, identical prompts, identical sampling. Throughput is recorded in `meta.json` and is **not** a comparison: the models ran on different GPUs and different engines.

Bonsai 2 27B PTQ1_0 is a ternary quantization of Qwen3.8-27B. The other side is GPTQ-Int4 of that same base. This measures what the 8 GB ternary pack retains on a coding battery, not "which company wins."

## Tasks

Eight prompts in `harness/prompts.jsonl`:

| id | name | what it asks |
|---|---|---|
| T01 | go-handler | stdlib Go `http.HandlerFunc` with an injected store |
| T02 | ts-bugfix | find defects in a Next.js route, return a corrected file |
| T03 | n8n-code-node | one Code node, run-once-for-all-items |
| T04 | sql-migration | idempotent PostgreSQL 16 migration |
| T05 | log-diagnosis | first-boot Postgres Docker flake |
| T06 | refactor-tests | refactor a fee function and write table-driven tests |
| T07 | long-context | three planted defects in a generated Go file |
| T08 | tool-call | JSON tool-call sequence against a tiny schema |

T07's fixture is generated by `fixtures/gen_longctx.py` so the planted key is reproducible. The key lives in that script, not in the Go file.

## Sampling

temperature 0.2, top_p 0.95, seed 1729, one sample. Ornith-1.5-9B used the same values on the same card. Single-sample scoring on reasoning models is noisy; the same prompt and seed produced different token counts across Bonsai passes (T01: 13,219 then 9,688). That is stated, not hidden.

`max_tokens` 60000 (T07: 45000). Client timeout 7200 s for the scored Bonsai pass. An earlier 1800 s ceiling cut Bonsai off mid-think; those cuts are not scored as model failures.

## Scoring

| Axis | Range | Meaning |
|---|---|---|
| Correctness | 0-5 | Does it do what was asked, and would it run? |
| Instruction following | 0-3 | Constraints honored |
| Concision | 0-2 | No unrequested commentary |
| Hallucination | flag | Invented API / package / column / tool; listed, never netted |

Max 10 per task, 80 for the suite.

A mechanical failure caps Correctness at 2 for that task. Mechanical checks:

| Task | Check |
|---|---|
| T01 | gofmt, go vet, go build |
| T02 | inspection plus presence of await / returned 404 / null id |
| T03 | `node --check`, then execute against a frozen-clock fixture |
| T04 | apply twice on PostgreSQL 16 |
| T05 | graded against the known cause (temporary initdb server) |
| T06 | `go test` on the model's own tests |
| T07 | answers vs the planted key in `gen_longctx.py` |
| T08 | JSON parse; tool names and required args vs the schema |

Grading was not blind for this publication. `harness/RUBRIC.md` describes a blind A/B procedure that was not completed; scores here are open, with the raw answers in `runs/` so a third party can re-grade.
